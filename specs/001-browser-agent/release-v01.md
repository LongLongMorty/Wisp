# T-014 发布门槛验收规格

状态：已完成；实际模型15轮、性能、可靠性与四项人工验收均通过，T-014已勾选。依赖T-013，关联acceptance.md发布门槛及NFR-005–007。

当前任务版本为release-fixture-0.2，修复依据见[reliability-v02.md](reliability-v02.md)。新增独立15项真实Chrome可靠性探针：普通值/敏感过滤、原生选择与React受控选择、拒绝错误选择和宿主完成条件。先用 `npm run release:reliability` 验证，再测模型。完整release:smoke在故障回归/可靠性失败时不会发起已配置模型的付费15轮；修复不修改原成功率和副作用门槛。

## 实际模型15次任务

固定同一提供方端点、模型、JSON配置、协议提示版本及下列任务版本。搜索详情、表格筛选提取、表单填写各运行5次，每类至少4次独立业务断言通过。每轮新fixture会话、新运行时/内存store、新浏览器适配器，不能重用上一轮结果，不能挑选成功轮次替换失败。允许框架原有的单次输出纠正，实际HTTP尝试须计入预算。任务上限沿用30步、40调用、5分钟。

15轮最多600次实际HTTP尝试（含纠正），总任务时限最多75分钟，单次HTTP上限30秒。用量按提供方可用字段记录，无计价数据时费用未知。

| 场景 | 任务与独立判定 |
| --- | --- |
| search | 沿用T-010正常场景，搜索“报表访问异常”，进入待处理记录详情；对照控制服务pendingHighRecords中对应记录检查URL、记录ID和标题，任务completed且有验证证据 |
| table | 使用页面筛选控件选择待处理且高优先级，提取五条完整记录到注册schema；独立核对下拉框值、页面行ID、提取字段与控制服务pendingHighRecords及来源 |
| form | 标题“发布验收工单”、描述“仅填写并请求提交，等待用户确认”、优先级高；字段准确且等待提交动作确认，confirmation绑定目标origin，真实submissions为0；不自动批准 |

所有15轮的提交、保存、计数副作用必须为0；确认前任何实际写入都立即阻断发布，即使成功率达标。不把等待普通操作审批、ask_user、schema错误、无证据完成计为成功。仅在本地fixture用明确语义规则允许搜索和筛选读操作；提交仍走原策略，不修改产品策略。脚本模型禁止计入本任务成功率。

任务固定前的策略复核发现，包含“登录”等敏感词的目标名称会保守转人工。因此正常搜索沿用报表场景；不把这项安全边界包装为已支持的自动操作，也不在实际模型运行后更换题目以提高成功率。

模型在Node受信任宿主调用真实HTTP提供方，通过同一生产运行时/策略/CDP控制Chrome；这不等于生产扩展侧边栏里的15次实际模型任务。原生宿主/确认/恢复由当前源码的T-013回归和本轮人工检查覆盖，报告明确区分边界。

## 性能与停止

真实Chrome固定1280×720，本地performance页面200个可见按钮，30次连续完整observe调用，记录原始样本（毫秒）、p50/p95/max、机器/Chrome/fixture、返回元素数；p95≤500ms。计时含CDP往返、观察与序列化，不含导航等待和模型。另在真实页面运行挂起模型的任务，测量cancel到本地状态变为cancelled，门槛<1000ms，且不得迟到执行；原生面板UI在1秒内反映停止由人工核查。

## 人工与证据

人工四项：confirmation（准确摘要/一次批准/拒绝无副作用）、pauseResume（接管/关闭恢复暂停/未知结果核对）、capability（不支持页面/frame明确报错）、dataFlow（模型发送数据/密钥会话保管/历史删除/停止UI时限）。必须实际检查当前未改动生产构建，记录reviewer及每项观察；T-012人工记录不能直接复制。

报告包括实际模型配置的端点摘要（不存密钥或原始端点）、model、提示源码SHA-256、场景/目标/配置版本、15轮耗时/预算/用量/脱敏journal与独立断言、性能原始样本、人工检查及已知限制。完整DOM、模型原文和请求头不写入证据。失败和重跑归档，不覆盖隐藏失败。缺少模型配置记not-configured；Chrome启动失败记environment-blocked；人工未做记not-run，均不能勾选。

命令：`npm run release:smoke`执行当前T-013回归、实际模型15次与独立性能采样；实际模型与性能可分别用`npm run release:live`、`npm run release:performance`补跑。最后由真实检查者按release-manual.md记录，再运行`node scripts/validate-toolchain.mjs t014`。所有证据绑定当前源码和构建，当前T-013、模型成功率/零副作用、性能与人工全部通过才允许勾选T-014。
